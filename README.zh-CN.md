# 证据驱动的交易桌

这是一个事件驱动交易系统工程项目的公开、洁净室说明。项目优先关注正确的财务状态、风险边界、可复现验证和诚实的研究结论，而不是好看的回测或高交易量。

> **范围说明。** 本仓库描述的是受控的研究与工程练习，不构成投资建议、实盘交易产品或盈利认证。

## 项目展示的能力

系统包含三个独立运行的组件：

1. **主动执行组件**：对有边界的信号作出反应；
2. **被动报价组件**：提供小规模、受库存约束的报价；
3. **组合风险组件**：重建组合敞口，并可降低超额风险。

这些组件共享行情观察和生命周期事件，但各自维护可单独归属的财务状态。这种分离是刻意设计：组合对冲可以降低桌面风险，却不会改变另一个组件自身的持仓容量。

## 工程原则

- **成交而非确认会改变财务状态。** 只有确认的成交证据才能更新持仓和现金。
- **理解订单生命周期。** 下单意图、确认回复、活跃生命周期、终态生命周期与成交是不同事实。
- **不确定时故障关闭。** 陈旧行情、模糊的请求结果、断连和关闭过程都会停止新增风险动作。
- **幂等记账。** 抑制真实的重复投递，但不会抹去组件级别合法的经济腿。
- **可复现的门槛。** 源码构建、聚焦测试、受控验证、全栈风险会话和清理检查被视为不同的证据层。

详见[架构](docs/ARCHITECTURE.md)、[验证](docs/VALIDATION.md)和[可复现性](docs/REPRODUCIBILITY.md)。

## 验证摘要

最终回归记录包括：

- Python 组件 33 项测试、研究与生产隔离 7 项测试、报价组件 46 项测试、对冲组件 52 项测试全部通过；
- 一次 5 分钟的受控报价压力运行，1,851 个已接受订单与 820 次成交，库存始终处于配置的 `[-2, +2]` 边界内；
- 三次独立的 10 分钟全栈会话，合计 1,807.196 秒；峰值绝对组合敞口为 8，加权平均绝对敞口为 1.014；
- 每次会话中独立账本均与内部账本一致，重复成交通知、重复活动报价、账本不一致、超时、异常和组件重启均为零；
- 有界启动、健康检查、停止和清理检查均通过。

这些是受控环境下的**正确性与有界风险**结果，而不是收益预测。

## 研究结论：刻意不作盈利宣称

经济研究得到的是负面且不确定的结论；保留这一结论，是因为它直接影响了生产选择：

- 固定的 1,200 个离线候选评估中，**零个**候选通过全部硬门槛。
- 随后的仅卖出研究候选方案在三次 60 秒屏测中均只成交 3 次，随后达到自身 `-3` 的持仓限额。
- 三次屏测中，参与度从比较方案的 163 笔成交下降到候选方案的 9 笔成交。因此，表面上的按市值计值改善只是描述性结果，并非可重复入场质量的证据。
- 严格的 500 毫秒成交后 markout 仅有 3 笔符合条件的成交，且全部不利：**-2.5、-2.0 和 -2.0 ticks**。
- 三个再循环/退出方案虽降低了饱和度，却未通过预先声明的最差情形和换手门槛；每个方案都需要约为参考方案 **100 倍**的动作倍数。

没有研究方案被推广为盈利策略。面向生产的默认选择仍是更保守、经过机械验证的设计。完整解释请参见[研究结果](docs/RESEARCH-RESULTS.md)。

## 运行洁净室领域核心

要求：Java 17+ 与 Maven 3.9+。

```bash
python -B tools/audit_publication.py .
mvn test
```

请在 Maven 生成被忽略的构建输出之前先运行发布边界审计。

三个 Maven 模块只包含与传输层无关的模型和测试：

- `common`：带符号的成交记账与不可变行情模型；
- `quoter`：被动报价决策与订单生命周期跟踪；
- `hedger`：组件级组合记账、精确投递去重与故障关闭的对冲状态机。

这些模块不会连接交易场所，也不会提交订单。仓库中的标识符与事件示例均为合成数据。
